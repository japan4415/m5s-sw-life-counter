## 目的とスコープ

### 目的

Magic: The Gathering の統率者戦（EDH / Commander）は 4 人対戦のフォーマットであり、各プレイヤーのライフと統率者ダメージを試合中に追跡する必要がある。本ファームウェアは現行の **for FaB** ファームウェアとは**別ファームウェア**として提供し、同一の M5Stack StopWatch Dev Kit ハードウェアに書き分ける。

カウントする対象は**ライフと統率者ダメージのみ**である。ルール裁定はプレイヤーが行う。本機はあくまで記録補助であり、敗北表示は目安にすぎない。

### スコープ外

以下の機能は本仕様の対象外とする。いずれも将来検討とする。

| 機能 | 除外理由 |
|------|---------|
| 毒カウンター | 追加カウンター種別の拡張として将来検討 |
| エネルギー・経験カウンター | 同上 |
| 統治者 / イニシアチブ | 状態トークンの管理は本機の範囲外 |
| ターン・時間管理 | ライフカウンターの本質的機能ではない |
| 4 人以外の人数（2 / 3 / 5 人以上） | 画面レイアウトが 4 分割専用設計のため |
| 共闘（1 プレイヤーが統率者 2 体を持つケース） | 被弾元を**プレイヤー単位**で記録するため、同一プレイヤーの 2 体の統率者を区別できない |

## ゲームルール要件

MTG 統率者戦のルール（MTG CR 903）に基づく要件を定義する。

### 初期ライフ

統率者戦の初期ライフは **40**（MTG CR 903.7）。メニューの Set Life で変更可能とするが、既定値は 40 とする。

### 統率者ダメージ

同一の統率者から**合計 21 点以上の戦闘ダメージ**を受けたプレイヤーは敗北する（MTG CR 903.10.1）。本機ではプレイヤー単位で 0〜99 の値を記録し、21 到達時に警告表示を行う。

共闘（Partner）で 1 プレイヤーが 2 体の統率者を持つ場合、MTG のルール上は統率者ごとに別カウントだが、本機は被弾元を**プレイヤー単位**で記録するため区別できない。この制限はスコープ外に明記している。

### ライフ連動

統率者ダメージは通常のダメージでもある。統率者ダメージを **+n** すると、同プレイヤーのライフも **-n** される。統率者ダメージを **-n**（修正）すると、ライフは **+n** 戻る。

v1 ではこの連動を**常時 ON** とし、統率者ダメージの増減とライフの増減を **1 操作**として処理する。Undo も一体で行う。

**設計判断の理由**: 統率者ダメージとライフを別々に入力する方式では、同じダメージを 2 回入力する（統率者ダメージ +n とライフ -n を個別操作する）ミスが不可避である。連動を常時 ON にすることで二重入力を防止し、操作ステップ数を削減する。

### クランプと連動の関係

統率者ダメージは **0〜99 でクランプ**する（99 は 2 桁表示のためのソフトクランプ上限）。ライフは 0 でクランプする（for FaB 版と同一）。

クランプにより実際の変化量が入力操作量と異なる場合、**ライフ連動は実際の変化量（クランプ後の差分）のみ反映**する。

**具体例**: 統率者ダメージが 2 の状態で -5 を操作した場合、統率者ダメージは 0 にクランプされる（実際の変化量は -2）。ライフ連動はクランプ後の差分に基づき +2 のみ戻る。

Undo は `lifeBefore` / `cmdDmgBefore` への直接復元で行うため、クランプが介在しても一意に正しく巻き戻る。

## 画面レイアウト

### 4 分割

円形画面を対角線（x 字）で 4 つの 90 度扇形に分割し、上・右・下・左の 4 プレイヤー（P1〜P4）に割り当てる。

```
通常時（ライフビュー）

              P1 (上)
           ╭──────────╮
          ╱ ╲   40   ╱ ╲
         ╱   ╲      ╱   ╲
        ╱     ╲    ╱     ╲
       ╱       ╲  ╱       ╲
P4(左)│   40    ╲╱    40   │P2(右)
      │         ╱╲         │
       ╲       ╱  ╲       ╱
        ╲     ╱    ╲     ╱
         ╲   ╱  40  ╲   ╱
          ╲ ╱        ╲ ╱
           ╰──────────╯
              P3 (下)

各扇形のテキストはプレイヤーの着席方向へ
回転して描画する（下表参照）。
```

### 回転描画

各扇形の表示内容はそのプレイヤーの着席方向へ回転して描画し、各自が自分の数値を正位置で読める。

| プレイヤー | 位置 | 回転角 | 説明 |
|-----------|------|--------|------|
| P1 | 上 | 180° | 対面のプレイヤーが読める向き |
| P2 | 右 | 270° | 右側のプレイヤーが読める向き |
| P3 | 下 | 0° | 手前のプレイヤーが読める向き（無回転） |
| P4 | 左 | 90° | 左側のプレイヤーが読める向き |

**4 人全員が同時に正位置で読める向きは存在しない。** 各プレイヤーは自分の扇形のみを正位置で読み、他プレイヤーの扇形は回転した状態で見ることになる。これは円形画面 1 台で 4 人分を表示する物理的制約である。

### プレイヤー識別

プレイヤーの識別は**位置**と**テーマカラー 4 色**で行う。テーマカラーの具体的な色は実装時に決定する。

### タッチの扇形判定

中心座標 (234, 234) からの相対座標 (dx, dy) で扇形を判定する。

```cpp
// 定数は config/app_config.hpp で定義する設定定数。
// ここではロジックの説明のためにリテラルで記述している。
float dx = touchX - 234.0f;  // kCenterX
float dy = touchY - 234.0f;  // kCenterY

if (std::abs(dy) > std::abs(dx)) {
    // 上下の扇形
    if (dy < 0) { /* P1 (上) */ }
    else        { /* P3 (下) */ }
} else {
    // 左右の扇形
    if (dx > 0) { /* P2 (右) */ }
    else        { /* P4 (左) */ }
}
```

`|dx| == |dy|` の境界上は左右の扇形（else 分岐）に入る。実用上、完全に `|dx| == |dy|` となるタッチは稀であり、ユーザー体験への影響は無視できる（実装で確定。詳細は後述「未確定事項」参照）。

### 半径方向の区分

現行 for FaB ファームウェアと同一の区分を踏襲する。

| 領域 | 半径範囲 (px) | 用途 |
|------|-------------|------|
| 外周操作リング | 165 以上（上限なし） | ライフ / 統率者ダメージの増減スライド。下限 165px は実測 p0 に基づく |
| 内側領域 | 165 未満 | タップ操作（ビュー切替・被弾元選択） |
| キャンセル領域 | 145 未満（設計値） | スライド中のキャンセル判定。外周リング下限 165 との間に 20px のヒステリシス |

## 操作体系

### 操作一覧

| 操作 | 動作 |
|------|------|
| 外周スライド（時計回り / 反時計回り） | **スライド開始位置の扇形のプレイヤー**のライフ +1 / -1。感度・一周あたり変動量 5 / 10 / 20 は for FaB 版と同一実装を共用 |
| 内側タップ（自分の扇形） | そのプレイヤーの表示をライフビュー <-> 統率者ダメージビューでトグル |
| 統率者ダメージビュー中: 他プレイヤーの扇形から開始した外周スライド | そのプレイヤーからの統率者ダメージを +1 / -1（ライフ連動）。被弾元はスライド開始扇形で決まる。感度設定はライフ操作と共用（操作感の統一のため） |
| 統率者ダメージビュー中: 自扇形から開始した外周スライド | 自分の通常ライフを +1 / -1（統率者ダメージは変化しない） |
| 統率者ダメージビュー中: 他プレイヤーの扇形へのタップ | 何もしない（タップは成立するがビュー状態・被弾元に影響しない） |
| 統率者ダメージビュー中: 内側再タップ or 無操作 10 秒 | ライフビューへ復帰。10 秒は設計値（実機調整前提） |
| KEYA 短押し | Undo（全プレイヤー共通の履歴を 1 手戻す） |
| KEYB 短押し | タッチロック切替 |
| KEYA + KEYB 長押し（1 秒） | ゲームメニュー |

### 補足ルール

**統率者ダメージビューの排他制御**: 統率者ダメージビューを開けるのは同時に 1 プレイヤーのみである。シングルタッチ制約と、操作の意味を一意に保つための制限である。あるプレイヤーのビューが開いている間、他扇形の内側タップは無視される（被弾元はスライド開始扇形で決まるため、タップによる選択は不要）。

**被弾元の決定方式**: 被弾元はスライド開始位置の扇形で決まる。統率者ダメージビューが開いている状態で、ビューを開いているプレイヤー以外の扇形から外周スライドを開始すると、その扇形のプレイヤーが被弾元となり統率者ダメージを増減する（ライフ連動）。ビューを開いているプレイヤー自身の扇形から外周スライドを開始した場合は、通常のライフ操作として扱う。

**内側タップの判定**: 「短時間で touch start -> end、移動量小」をタップとして判定する。現行の外周スライドのキャンセル領域（半径 145px 未満）とは別ロジックだが、既存の `GestureState` の Candidate -> Idle 遷移（外周リングに触れたが移動角不足で指を離す）の判定を内側領域へ拡張することで流用できる見込みである。

## 統率者ダメージビューの表示

### 表示内容

統率者ダメージビューでは、対象プレイヤーの扇形内に 3 対戦相手それぞれからの累計統率者ダメージを一覧表示する。

```
P3 が統率者ダメージビューを開いた場合:

              P1 (上)
           ╭──────────╮
          ╱ ╲   40   ╱ ╲
         ╱   ╲      ╱   ╲
        ╱     ╲    ╱     ╲
       ╱       ╲  ╱       ╲
P4(左)│   40    ╲╱    40   │P2(右)
      │         ╱╲         │
       ╲       ╱  ╲       ╱
        ╲     ╱    ╲     ╱
         ╲   ╱ CMD  ╲   ╱  ← P3 の扇形が
          ╲ ╱  VIEW  ╲ ╱     統率者ダメージ表示
           ╰──────────╯
              P3 (下)

P3 扇形の統率者ダメージ表示:
  P1 から:  5
  P2 から:  3
  P4 から:  0
```

### 表示ルール

- 被弾元は相手の**位置**と**テーマカラー**で示す
- 21 以上の被弾元は**警告色**で表示する

| 条件 | MTG ルール根拠 |
|------|---------------|
| ライフが 0 以下 | CR 704.5a |

## 画面状態機械

for FaB 版の画面状態を踏襲し、ACTIVE 内にプレイヤー毎のビュー状態をサブ状態として持つ。

### 画面状態

```
SETUP ── B(hold) 1秒 ──→ ACTIVE
                           ↕ A+B(hold) 1秒
                          MENU
          ┌────────┬──────┼──────────┬───────┬───────┐
        Resume  History  SetLife  Sensitivity  Rematch  About
          ↓       ↓       ↓         ↓        B(hold)確認  ↓
        ACTIVE  HISTORY  SETUP  SENSITIVITY    ACTIVE   ABOUT
                  ↓                 ↓                     ↓
             B短押し→ MENU   B短押し/A+B→ MENU      B短押し→ MENU
```

画面状態は for FaB 版と同一の **SETUP / ACTIVE / MENU / HISTORY / ABOUT / SENSITIVITY** の 6 つである。

### ACTIVE 内のビュー状態

ACTIVE 状態では、各プレイヤー（P1〜P4）が独立したビュー状態を持つ。ただし CmdDamageView は同時に 1 プレイヤーのみである。

```
各プレイヤーのビュー状態:

  LifeView ←─────────────────── CmdDamageView
     │                                ↑
     │ 内側タップ                      │ 内側再タップ
     ↓                                │ or 10秒無操作
  CmdDamageView ───────────────────────┘
     │
     │ 他扇形から外周スライド → 統率者ダメージ増減
     │ 自扇形から外周スライド → 通常ライフ増減
     ↓
  （操作確定後もビュー維持）
```

| ビュー状態 | 表示内容 |
|-----------|---------|
| LifeView | ライフ値を大きく表示（通常時） |
| CmdDamageView | 3 対戦相手の統率者ダメージ一覧を表示。被弾元はスライド開始扇形で決まる |

### ゲームメニュー

for FaB 版と同構成の 6 項目を踏襲する。

| メニュー | 動作 | 備考 |
|---------|------|------|
| Resume | ゲームに戻る | |
| History | ライフ変更履歴を表示 | 統率者ダメージ操作も含む。各エントリは対象・被弾元・変化量を 1 行で判別できる形式（例: `P3 <- P2  +5`）で表示する。詳細レイアウトは実装時に確定する |
| Set Life | 4 人一括の初期ライフを変更 | 既定 40 |
| Sensitivity | 一周あたりのライフ変動量を変更 | 5 / 10 / 20。ライフ操作・統率者ダメージ操作の両方に共用適用する |
| Rematch | 同じ初期ライフで試合をやり直す | B(hold) 長押し確認を要求 |
| About | ファームウェアバージョン表示 | |

## ドメインモデル（案）

既存の `lib/counter_core/domain/match_state.hpp` のスタイルに合わせたスケッチを以下に示す。あくまで仕様書段階の案であり、実装時に調整する。

```cpp
#include <cstdint>
#include "match_state.hpp"  // RingBuffer を共用

namespace counter::edh {

constexpr uint8_t kPlayerCount  = 4;
constexpr uint8_t kSourceNone   = 0xFF;  // 通常ライフ操作を示す

struct PlayerState {
    uint32_t startingLife;                      // 既定 40
    uint32_t life;                              // 0 でクランプ
    uint8_t  commanderDamageFrom[kPlayerCount]; // 自番号は未使用。0〜99
};

struct LifeChange {
    uint32_t sequence;      // 単調増加する通し番号
    uint8_t  playerIndex;   // 対象プレイヤー (0〜3)
    uint8_t  sourceIndex;   // 被弾元プレイヤー (0〜3)。kSourceNone = 通常ライフ操作
    int16_t  delta;         // 変更量
    uint32_t lifeBefore;    // 変更前のライフ値
    uint32_t lifeAfter;     // 変更後のライフ値
    uint8_t  cmdDmgBefore;  // 変更前の統率者ダメージ（通常操作時は未使用）
    uint8_t  cmdDmgAfter;   // 変更後の統率者ダメージ（通常操作時は未使用）
    uint32_t uptimeMs;      // 変更時点のシステム稼働時間
};

struct MatchState {
    uint16_t schemaVersion;
    PlayerState players[kPlayerCount];
    bool     active;
    bool     touchLocked;
    uint32_t nextSequence;
    counter::domain::RingBuffer<LifeChange, 16> history;  // 後述の理由で 64 → 16 に縮小
};

}  // namespace counter::edh
```

### フィールド補足

| フィールド | 説明 |
|-----------|------|
| `PlayerState::commanderDamageFrom[i]` | プレイヤー `i` の統率者から受けた累計ダメージ。0〜99 でクランプ（99 は 2 桁表示のためのソフトクランプ上限）。自分自身の番号（`i == 自プレイヤーインデックス`）は未使用 |
| `LifeChange::sourceIndex` | `kSourceNone`（0xFF）の場合は通常のライフ操作。0〜3 の場合は統率者ダメージ操作 |
| `LifeChange::delta` | 通常操作: ライフ変更量（正 = 増加、負 = 減少）。統率者ダメージ操作: 統率者ダメージ変更量（正 = ダメージ増加、負 = ダメージ減少）。ライフ変化量は実際の統率者ダメージ変化量（クランプ後の差分）の符号を反転した値となる（統率者ダメージ +3 -> ライフ -3）。ライフ連動分は本エントリで一体管理する |

### 履歴バッファサイズの変更（64 → 16）

当初は `RingBuffer<LifeChange, 64>` で設計したが、`LifeChange` 1 レコードが約 20 バイト、`MatchState` 全体では約 1,620 バイトとなり、NVS 16 スロットローテーション（NVS パーティション 20,480 バイト）で保存に失敗した。`RingBuffer<LifeChange, 16>` に縮小することで NVS パーティション内に収まるようになった。これにより Undo の深さは最大 **16 手**となる。

### Undo の意味論

Undo は差分の逆適用ではなく、`lifeBefore`（および `cmdDmgBefore`）への復元で行う。for FaB 版の Undo 意味論と同一の方針である。

- **通常ライフ操作の Undo**: `lifeBefore` にライフを復元する
- **統率者ダメージ操作の Undo**: `lifeBefore` にライフを復元し、`cmdDmgBefore` に統率者ダメージを復元する。1 操作で両方が巻き戻る

## 永続化

for FaB 版の NVS 16 スロットローテーション + CRC32 方式を踏襲する。

| 項目 | 値 |
|------|-----|
| NVS namespace | `"edh"`（for FaB 版とは別 namespace） |
| schemaVersion | EDH 固有のバージョン番号（for FaB 版とは独立） |
| スロット数 | 16（ローテーション） |
| 検証 | CRC32 |

for FaB 版のデータと干渉しない設計とする。永続化方式の詳細は [./08-persistence.md](./08-persistence.md) を参照。

| ジェスチャー判定 | `GestureState` の状態遷移、角度計算、角速度フィルタ |

| ボタン状態機械 | 短押し / 長押し / 同時押しの判定 |
| NVS 永続化方式 | 16 スロットローテーション + CRC32 |
| 振動フィードバック | パルス制御 |
| 感度設定 | プリセット管理と NVS 永続化 |

### ビルド構成

PlatformIO の別ビルド（`env` またはプリプロセッサフラグ）で for FaB / for MTG EDH を書き分ける。1 つのリポジトリ内で複数ファームウェアバリアントを管理する。

### Web Flasher

Web Flasher でのファームウェアバリアント選択への対応は本仕様の範囲外とする。将来の別 PR で対応し、[./14-web-flasher-design.md](./14-web-flasher-design.md) への影響として扱う。

## 未確定事項・実機調整前提

以下の項目のうち、実装で設計値が確定したものと、実機テストで確認が必要なものを区別して示す。

### 実装で確定した設計値

| 項目 | 設計値 | 確認元 |
|------|--------|--------|
| 扇形境界（`\|dx\| == \|dy\|`）の扱い | 左右の扇形（else 分岐）に入る。不感帯は設けない。将来的に必要になった場合は `absDy` と `absDx` の差が閾値未満のときに入力を無視する方式を検討する | `lib/edh_core/input/edh_touch_zone.cpp` L34-40 |
| 内側タップ判定の許容移動量 | 20 px（`kTapMaxMovePx`）。移動量の 2 乗で比較する実装 | `lib/edh_core/input/edh_touch_zone.hpp` L28、`src/app/edh_app_controller.cpp` L889-890 |
| 内側タップ判定の許容時間 | **600 ms**（`kTapMaxDurationMs`）。当初 300 ms で設計したが、タッチセンサに中央値 15ms 間隔・最大 270ms の欠測があり（`docs/01-hardware.md`）、物理的な 200ms のタップが欠測により 470ms として観測されうるため 300ms では通常のタップが棄却された。600 ms は欠測を考慮しつつ長押し操作との誤判定を避けるバランスとして実機検証を経て確定した | `lib/edh_core/input/edh_touch_zone.hpp` L31-35、`src/app/edh_app_controller.cpp` L896 |
| ビュー復帰タイムアウト | 10,000 ms（`kViewTimeoutMs`） | `lib/edh_core/app/edh_screen_state.hpp` L90 |
| スライド開始角度の判定（EDH 専用） | FaB 用の `isValidStartAngle()` は 0 度（右端）・180 度（左端）付近を禁止するが、EDH の P2（右）・P4（左）の中心角と重なるため左右のスライドが効かなかった。EDH では 4 扇形の境界（45/135/225/315 度 = 対角線）付近のみを不感帯とする `isValidStartAngleEdh()` を導入した。不感帯の半幅は `kEdhDeadZoneHalfWidthDeg = 15.0f` 度（例: 45 度 ± 15 度 = 30〜60 度が不感帯）。P2/P4 の座標を GestureDetector に渡す際は 90 度反時計回りに回転させて FaB 用禁止領域を迂回する（`rotateCCW90()`） | `lib/edh_core/input/edh_touch_zone.hpp` L39-56, L59-75 |
| 4 扇形の描画方式 | 当初は 234x234 の矩形キャンバスで各扇形を描画する設計だったが、隣接キャンバスの重なりにより表示が壊れたため、**100x80 の互いに重ならないキャンバス**を画面中心から半径 105px の位置に配置する方式に変更した。キャンバスサイズ: `kSectorCanvasW = 100`、`kSectorCanvasH = 80`。配置半径: `kSectorPlacementR = 105`。キャンバス端の最大距離は約 160px で、外周リング下限（半径 165px）に干渉しない | `src/ui/edh_theme.hpp` L125-132、`src/ui/edh_renderer.cpp` L33-53 |

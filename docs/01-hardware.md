## タッチパネルの実測特性

Phase 0 Step 3 の実機計測（2026-08-17、826 サンプル）で得られた CST820B タッチ IC の特性データを以下に整理する。

### サンプリング特性

| 指標 | 実測値 |
|---|---|
| サンプリング間隔 中央値 | 15 ms（約 66 Hz） |
| サンプリング間隔 最大 | 270 ms（欠測が起きる） |

サンプリング間隔には大きなばらつきがあり、最大 270 ms の欠測が発生する。ジェスチャー判定において「1 サンプルあたりの座標変化量」を固定閾値で異常判定すると、サンプル落ち時に誤検出する。経過時間で正規化した速度で判定する必要がある。

### タッチ座標範囲

| 指標 | 実測値 |
|---|---|
| x 座標範囲 | 18 〜 465 |
| y 座標範囲 | 14 〜 466 |
| 中心 (234, 234) からの半径 最小 | 165.0 |
| 中心 (234, 234) からの半径 中央値 | 209.3 |
| 中心 (234, 234) からの半径 最大 | 268.2 |
| 表示円（半径 234）より外側のサンプル数 | 826 件中 117 件（14.2%） |

**重要**: タッチ IC（CST820B）は**表示領域の円（半径 234）より外側の座標を返す**。丸型 AMOLED の見た目の縁とタッチの有効範囲は一致しない。外周を使う UI では、半径の上限で入力を弾くと正当な操作を落とすことになる。

### 回転方向と `atan2()` の符号

- **ユーザーから見て時計回りになぞると `atan2(dy, dx)` の値は増加する**（一周で +363.6 度、反時計回りは -372.3 度）
- 画面座標系は y が下向きに増えるため、数学的な標準（反時計回りが正）とは逆になる
- この特性は `config/app_config.hpp` に回転符号の定数として反映する

## 振動モーターの実測特性

Phase 0 Step 5 の実機確認（2026-08-17）で得られた振動モーターの特性データを以下に整理する。

### 制御の仕組み

振動モーターは M5IOE1（IO エキスパンダ）の `pwm_ch1`（**GPIO9**）を経由して 12bit PWM で駆動される。API は `M5.Power.setVibration(uint8_t level)` であり、**引数 `level` は持続時間ではなく強度（0〜255）**を指定する。内部では `duty12 = level * 0x0FFF / 255` に変換される。

`setVibration(0)` を明示的に呼ぶまでモーターは回り続ける。時間制御は呼び出し側で `millis()` 等を使って管理する必要がある。

### 実測結果

| 指標 | 実測値 |
|---|---|
| 体感できた最低強度 | 255（それ未満の 32〜192 では体感できず） |
| 強度 255 での最低体感持続時間 | 15 ms（かろうじて）、20 ms（確実） |

### 実用パラメータの制約

- **強度は設計変数にできない**: 255 でのみ体感可能であり、強弱の表現は不可能
- **持続時間で表現を分ける**: 振動フィードバックの種類（tick / 確定 / 警告）は時間の長短でのみ区別する

## USB とプログラミング

| 項目 | 値 |
|---|---|
| コネクタ | USB Type-C |
| 通信方式 | Native USB-CDC（ESP32-S3 内蔵 USB OTG） |
| USB-Serial 変換 IC | なし（CH9102 / CP210x / CH340 は不使用） |
| USB D+ / D- | GPIO 20（D+） / GPIO 19（D-） |
| macOS ドライバ | 不要（macOS 11 以降はドライバレスで認識） |
| macOS ポート名 | `/dev/cu.usbmodem*` 形式 |

### ダウンロードモード

電源ボタンを約 2 秒長押しし、緑 LED が点灯した時点で離すと書き込み待機状態に入る。

### 強制ブートローダーモード

ブートループや文鎮化した場合に使用する。Boot ボタン（GPIO0）を押しながら USB-C ケーブルを抜き差しする。

> **注意**: Boot ボタン（GPIO0）の物理的位置は公式ドキュメントに明記されていない。KEYA（GPIO2）/ KEYB（GPIO1）とは別のボタンであると推測される。要実機確認。

| 項目 | 値 |
|---|---|
| バッテリー容量 | 450 mAh |
| 電源管理 IC | M5PM1（マルチレベル電源管理） |
| 給電 | USB Type-C DC 5V |
| バッテリー残量確認 | 画面上端から中心へスワイプ |
| 背面 | マグネット（卓上台座への固定用） |

### バッテリー API の実測結果（2026-08-17）

| API | 戻り値 | 備考 |
|---|---|---|
| `M5.Power.getBatteryLevel()` | 0〜100（%） | 正常に取得可能 |
| `M5.Power.getBatteryVoltage()` | mV 単位 | 正常に取得可能 |
| `M5.Power.isCharging()` | bool | 満充電時は **false** を返す（後述） |
| `M5.Power.getBatteryCurrent()` | -- | **使用不可**。ハードウェア制限により StopWatch ではバッテリー電流を読み取れない（公式記載） |
| `M5.Power.getVBUSVoltage()` | mV 単位 | USB 給電判定に利用可能（後述） |
| `M5.Power.M5pm1.getPowerSource()` | 列挙値 | 電源種別の判定に利用可能（後述） |

> **重要**: USB 接続中・満充電時に `getBatteryLevel()` = 100、`isCharging()` = false（0）が返った。満充電になると充電回路が停止するため `isCharging()` は false になる。したがって、**`isCharging()` を「USB 給電中かどうか」の判定に使うのは不適当**である。

> **解決済み（2026-08-18）: USB 給電の判定手段**: `M5.Power.getVBUSVoltage()` で USB 給電の有無を判定できることが判明した。USB 接続時は約 4800〜5100 mV、未接続時は約 0 mV を返す。満充電時でも USB が接続されていれば値が出るため、`isCharging()` の制限を回避できる。`M5.Power.M5pm1.getPowerSource()` も電源種別の判定に使える。**ただし現時点ではこれらの API を実装に使用していない**。Phase 3 の電源管理で適用する想定である。

## 電源ボタンの検出制限（2026-08-18 実機調査で確定）

M5Unified のソースコード調査により、**電源ボタンの押下をアプリケーションから検出することはできない**ことが判明した。

### 技術的な根拠

- `M5.Power.getKeyState()` API は存在し、M5Unified の StopWatch コードパスにも繋がっている
- しかし、**M5Unified の StopWatch 初期化が M5PM1 の IRQ ピンを設定していない**
- IRQ ピン未設定の場合、**M5PM1 は IRQ ステータスを自動クリアする**ため、ボタン押下イベントを取りこぼす。M5Unified 自身がソースコード中にこの旨を注記している
- 公式ドキュメントによれば **GPIO12 が M5PM1 の IRQ 出力に配線されている**（`G12_PY_IRQ`）が、M5Unified ライブラリはこの GPIO を IRQ として設定していない

### 設計への影響

「電源ボタンを押したらスリープに入る」という一般的な操作は実装できない。代替として、スリープ機能はゲームメニューの項目として提供している（ADR-22 を参照）。

## ライトスリープでの GPIO 設定の罠（2026-08-18 実機で確認）

ESP32-S3 のライトスリープを GPIO ウェイクアップと組み合わせる場合、**M5Unified（M5GFX）の `pinMode(INPUT)` がスリープ時のピン設定を破壊する**問題がある。

### 問題の詳細

- **ESP32-S3 のライトスリープでは、既定で GPIO がスリープ用レジスタ（SLP_*）の設定に切り替わる**
- M5Unified（M5GFX）の `pinMode(INPUT)` は**スリープ時プルアップ（SLP_PU）をクリアする**ため、スリープ中にピンがフローティングになる
- フローティング状態では、ボタン押下（LOW）を検出できず、GPIO ウェイクアップが機能しない

### 対処方法

スリープ前に以下の設定を明示的に行う:

1. `gpio_sleep_sel_dis(pin)` で SLP_SEL を無効化し、通常設定をスリープ中も維持する
2. `gpio_set_direction(pin, GPIO_MODE_INPUT)` で入力方向を明示的に設定する
3. `gpio_pullup_en(pin)` でプルアップを明示的に有効化する

### ボタンの GPIO 接続

KEYA と KEYB は **GPIO 直結**であり、M5IOE1（IO エキスパンダ）経由ではない。`M5Unified.cpp` の `board_M5StopWatch` 分岐で確認済み。

| ボタン | GPIO |
|--------|------|
| KEYA（黄色） | GPIO 2 |
| KEYB（青色） | GPIO 1 |

### 実機で起きた事故

ライトスリープを `gpio_sleep_sel_dis()` なしで実機に書き込んだ結果、**スリープから復帰できず USB シリアルも消失し、書き込み不能になった**。電源ボタン長押しでダウンロードモードに入れて復旧する必要があった。この事故から、**スリープには必ず復帰手段を 2 つ用意すること**（GPIO ウェイクアップ＋タイマーウェイクアップ）を方針として確立した（ADR-23 を参照）。

## 既知の注意点

- **`BAT` ラベルの誤記**: 公式ドキュメントにおいて、`BAT` と表記されたピンは実際には `5V IN`（外部電源入力用）であり、バッテリー端子ではない。ハードウェア接続時に誤接続しないよう注意が必要である。

- **Grove EXT_5V の初期状態**: Grove コネクタの 5V 出力は初期状態で入力モードになっており、`M5.Power.setExtOutput(true)` を呼ばないと 5V が出力されない（公式記載）。Grove に 5V 給電が必要な外部モジュールを接続する場合は `setup()` で明示的に有効化すること。

## 設計へのハードウェア含意

以下は、ハードウェア仕様がソフトウェア設計に与える影響をまとめたものである。

### 円形画面と外周スライド操作

468 x 468（実測値）の円形 AMOLED は四隅が存在しないため、矩形 UI のレイアウト手法をそのまま適用できない。画面中心座標は (234, 234) であり、画面中央からの距離と角度（極座標）でレイアウトを考える必要がある。一方、円形の縁は外周リング操作との相性が極めて良く、本プロジェクトの操作体系はこのハードウェア特性を活かした設計である。

**タッチ有効範囲と表示円の不一致（実測確認済み）**: タッチ IC（CST820B）は表示円（半径 234）より外側の座標を返す（実測で最大半径 268.2、826 件中 117 件が表示円外）。外周操作の判定に半径の**上限を設けてはいけない**。上限で入力を弾くと正当な操作を落とすことになる。

### タッチのサンプル落ちとジェスチャー判定

タッチ IC のサンプリング間隔は中央値 15 ms（約 66 Hz）だが、最大 270 ms の欠測が発生する（実測確認済み）。このため、ジェスチャー判定は「1 サンプルあたりの変化量」ではなく**経過時間で正規化した速度**で行う必要がある。固定値の変化量閾値ではサンプル落ち時に誤検出する。

### PSRAM 8 MB

フルフレームバッファ（約 427.8 KiB）を PSRAM 上の `M5Canvas` に確保できることを実測で確認した（438,068 bytes 消費、確保後の空き 7,509,919 bytes）。8 MB のうちフレームバッファが占める割合は約 5% であり、将来のイベントログバッファやフォントデータにも十分な余裕がある。ただし全画面一括転送は 22.4 FPS（44.6 ms/回）であり、描画方式としては部分再描画が必要である（後述「全画面転送のコストと部分再描画」参照）。

### Native USB-CDC

USB-Serial 変換 IC を介さないため書き込みが高速である一方、起動直後はまだ USB-CDC が初期化されていないためシリアルログの冒頭を取りこぼしやすい。デバッグ時は起動後のログ出力開始を待つか、十分なディレイを入れる工夫が必要になる場合がある。また、アップロード後にポート名（`/dev/cu.usbmodem*` の番号部分）が変わることがある。

### ボタン 2 個のみ

KEYA と KEYB の 2 個しかプログラマブルボタンがないため、割り当ては実質的に以下が必然となる。実機確認（2026-08-17）により、画面正面から見て**左が BtnA（KEYA）、右が BtnB（KEYB）**であることが確定した。

| 操作 | 動作 | 物理位置（画面正面視） |
|---|---|---|
| Button A 短押し | Undo | 左ボタン |
| Button B 短押し | タッチロック切り替え | 右ボタン |
| A + B 長押し（1 秒） | ゲームメニュー | 左右同時 |

電源ボタンは電源 ON（短押し）/ 電源 OFF（素早く 2 回押し）に使用し、ゲーム操作には割り当てない。

### 振動は強度を設計変数にできない

実測（2026-08-17）により、`M5.Power.setVibration()` の強度パラメータは 255 でのみ体感可能であることが判明した（32〜192 では体感できず）。したがって、振動フィードバックの種類（tick / 確定 / ライフ 0 警告）を強弱で表現することはできない。**時間の長短でのみ表現する**設計とする。最低体感持続時間は 15 ms（かろうじて）/ 20 ms（確実）であるため、最短の tick 振動でも 20 ms 以上を設定する必要がある。

### 全画面転送のコストと部分再描画

実測（2026-08-17）により、PSRAM 上の全画面 Canvas（468x468）を画面に転送する時間が確定した。

| 方式 | 転送時間（中央値） | FPS |
|---|---|---|
| 全画面 468x468 | 44,639 us | 22.4 |
| 上半分 468x234 | 22,312 us | 44.8 |
| 中央 200x120 | 4,994 us | 200.2 |

全画面一括転送は 22.4 FPS であり、30 FPS の目安を下回る。**UI は部分再描画を前提に組む必要がある**。ライフ数値の変更時は数値エリアのみ転送し、背景や外周リングは変更時のみ再描画する設計とする。上半分転送（44.8 FPS）はプレイヤーエリア単位の更新として実用的であり、中央小領域（200.2 FPS）は数値更新に十分高速である。

### バッテリー 450 mAh

目標稼働時間は連続 4 ~ 8 時間（Wi-Fi / Bluetooth 無効、輝度 30 ~ 40%、振動有効）であるが、この数値は実測で確認する必要がある。大会で使用する場合、USB-C での給電を前提にするか、外付けモバイルバッテリーを併用する運用も検討に値する。

### 電源レール構造

M5PM1（電源管理 IC）が管理する電源レールの階層構造は以下のとおりである（出典: [公式ドキュメント](https://docs.m5stack.com/en/arduino/stopwatch/m5pm1_m5ioe1)）。

| レベル | 供給先 |
|--------|--------|
| L0 | バッテリー → M5PM1（電源ボタンの ON/OFF 機能はここに依存） |
| L1 | IMU、RTC |
| L2/L3A | ESP32-S3、Grove 3.3V、M5IOE1、ボタン pull-up |
| L3B | AMOLED、スピーカー、バイブレーション（M5IOE1 経由） |

AMOLED ディスプレイ・スピーカー・バイブレーションモーターは M5IOE1（IO エキスパンダ）配下の L3B レールに接続されている。これらの周辺機器を使用するには M5IOE1 の初期化が必要である。`M5.begin()` は M5IOE1 を自動的に初期化するが、独自の初期化手順を実装する場合はこの依存関係に注意すること。

### 公式 `platformio.ini` の追加ライブラリ

公式ドキュメントの `platformio.ini` には M5Unified / M5GFX に加え、以下のライブラリが含まれている。

| ライブラリ | 役割 |
|-----------|------|
| M5PM1 | 電源管理 IC（M5PM1）の制御。電源レール管理 |
| M5IOE1 | IO エキスパンダ（M5IOE1）の制御。AMOLED・スピーカー・バイブレーション等の周辺機器管理 |

本プロジェクトの MVP では `M5.begin()` が内部でこれらを初期化するため、直接の利用は不要である。ただし電源管理やスリープ制御を細かくカスタマイズする場合は、これらのライブラリの API を直接使用する可能性がある。

一次資料で確度が低いとされている項目のうち、ハードウェアに関わるものを以下に整理する。

| 項目 | 確認方法 | 備考 |
|---|---|---|
| Arduino IDE のボード名 `M5StopWatch` | Board Manager インストール後に IDE 上で目視確認 | 大文字小文字やスペルが異なる可能性がある |
| Boot ボタン（GPIO0）の物理位置 | 実機で各ボタンを押しながらリセットし、ブートローダーに入るボタンを特定 | KEYA / KEYB とは別の専用ボタンである可能性が高い |
| BLE の実動作 | 実機で BLE advertising を起動し、スマホから接続を試みる | 製品ページでは Wi-Fi のみ明記。SoC 的には BLE 対応だが基板上の RF パスが有効かは未確認 |
| 連続稼働時間 | Wi-Fi / Bluetooth 無効・輝度 30 ~ 40%・振動有効の条件で実測 | 目標は 4 ~ 8 時間。バッテリー 450 mAh は公式確認済み |

### 実機確認済み項目

以下は Phase 0 の実機確認で確定した項目である。

| 項目 | 結果 | 備考 |
|---|---|---|
| PlatformIO の board 文字列 | `esp32s3box`（公式指定） | PlatformIO に StopWatch 専用のボード定義は存在しない（`pio boards \| grep -i stopwatch` で 0 件）。[公式ドキュメント](https://docs.m5stack.com/en/core/StopWatch)が明示的に指定 |
| 電源ボタン操作 | 短押し: 電源 ON/リセット。素早く 2 回押し: 電源 OFF。約 2 秒長押し: ダウンロードモード | [公式ドキュメント](https://docs.m5stack.com/en/core/StopWatch)に記載 |
| ディスプレイ解像度 | 468 x 468（実測値） | 公式仕様は 466 x 466 だが、`M5.Display.width()` / `M5.Display.height()` の実測値は 468 x 468。設計は実測値を採用 |
| フレームバッファサイズ | 438,048 bytes ≈ 427.8 KiB | 468 x 468 x 2 byte（RGB565） |
| 画面中心座標 | (234, 234) | 468 / 2 = 234 |
| PSRAM 空き容量 | 約 7.9 MB（7,947,987 bytes） | `ESP.getFreePsram()` の実測値（`M5.begin()` 直後） |
| Flash サイズ | 16 MB（16,777,216 bytes） | `ESP.getFlashChipSize()` の実測値 |
| ビルドサイズ（最小構成） | RAM 6.7%（21,920 / 327,680 bytes）、Flash 7.6%（498,965 / 6,553,600 bytes） | M5Unified + M5GFX の最小スケッチ |
| 解決されたライブラリ | M5Unified 0.2.20 / M5GFX 0.2.27 | 公式要件 >=0.2.15 / >=0.2.21 を満たす |
| タッチ座標系と `atan2()` の符号 | 時計回りで角度が増加（+363.6 度/周） | 画面座標系は y 下向きのため、数学的標準（反時計回りが正）と逆。826 サンプルで確認（2026-08-17） |
| ボタンの物理位置（左右対応） | 画面正面視で左 = BtnA（KEYA / GPIO2）、右 = BtnB（KEYB / GPIO1） | 設計上 左=Undo、右=タッチロック。実機で確認（2026-08-17） |
| タッチ IC のサンプリング特性 | 中央値 15 ms（約 66 Hz）、最大 270 ms の欠測あり | サンプル落ちのためジェスチャー判定は経過時間で正規化が必要（2026-08-17） |
| タッチ座標の有効範囲 | x: 18〜465、y: 14〜466、最大半径 268.2 | 表示円（半径 234）より外側の座標が 826 件中 117 件（14.2%）（2026-08-17） |
| 180 度回転描画 | 実機目視で正しく表示されることを確認 | 上側プレイヤー用の回転描画が正常動作（2026-08-17） |
| 振動モーター特性 | 強度 255 でのみ体感可能。15 ms かろうじて、20 ms で確実 | M5IOE1 GPIO9 の 12bit PWM 駆動。32〜192 は体感不可（2026-08-17） |
| バッテリー API | `getBatteryLevel()` / `getBatteryVoltage()` 取得可。`isCharging()` 満充電時 false | `getBatteryCurrent()` は HW 制限で使用不可。USB 給電判定は `getVBUSVoltage()` で可能（手段判明、実装未適用）（2026-08-17〜18） |
| PSRAM 全画面 Canvas 確保 | 468x468 16bit を PSRAM に確保成功。438,068 bytes 消費、空き 7,509,919 bytes | 期待値 438,048 bytes とほぼ一致（2026-08-17） |
| 描画レート（3 方式） | 全画面 44,639 us（22.4 FPS）/ 上半分 22,312 us（44.8 FPS）/ 中央 4,994 us（200.2 FPS） | 全画面は 30 FPS 目標未達。部分再描画が必要（2026-08-17） |
| 電源ボタンのアプリ検出 | **検出不可** | M5Unified が M5PM1 の IRQ ピン（GPIO12）を設定しないため、`getKeyState()` でボタン押下を取得できない（2026-08-18） |
| ライトスリープ GPIO ウェイクアップ | `gpio_sleep_sel_dis()` が必須 | M5Unified の `pinMode(INPUT)` が SLP_PU をクリアするため、対処なしではスリープ中にピンがフローティングになり復帰不能（2026-08-18） |
| ボタンの GPIO 接続方式 | GPIO 直結（KEYA=GPIO2 / KEYB=GPIO1） | M5IOE1 経由ではない。`M5Unified.cpp` の `board_M5StopWatch` 分岐で確認（2026-08-18） |
| USB 給電判定手段 | `getVBUSVoltage()` で判定可能（USB 接続時 約 4800〜5100 mV、未接続時 約 0 mV） | 手段は判明したが実装には未適用。Phase 3 で使用予定（2026-08-18） |

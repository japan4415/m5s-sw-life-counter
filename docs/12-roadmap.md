## Phase 0: 実機成立性確認

Phase 0 はハードウェアの動作を確認し、以降のフェーズで必要となる定数と設計判断を確定させる段階である。一次資料の初期設計にはこの段階が明示されておらず、モバイル連携版で追加された BLE 成立性確認と、ハードウェア動作確認を統合して構成した。

### 確認項目と進捗（2026-08-17 時点）

| 項目 | 確認内容 | 状態 |
|------|---------|------|
| デバイス同定 | SoC・Flash・PSRAM・ディスプレイの確認 | **確認済み**: ESP32-S3 (QFN56) rev v0.2、Flash 16 MiB、PSRAM 約 7.58 MiB |
| ディスプレイ解像度 | AMOLED の解像度確認 | **確認済み**: 実測 468x468（公式仕様 466x466 と食い違い。設計は実測値を採用） |
| PSRAM 上の `M5Canvas` 確保 | 468x468x2 bytes（約 427.8 KiB）のバッファを PSRAM 上に確保できること | **確認済み**: 468x468x16bit Canvas 確保成功。消費 438,068 bytes、確保後空き 7,509,919 bytes |
| ビルド・書き込み | PlatformIO でのビルドと M5Stack への書き込み | **成功**: M5Unified 0.2.20 / M5GFX 0.2.27、RAM 6.7%、Flash 7.6% |
| 電源ボタン操作 | 電源 ON/OFF とダウンロードモードの操作 | **公式記載で確定**: 短押し=ON、2回押し=OFF、長押し=ダウンロードモード |
| 画面描画 | M5GFX による 468x468 AMOLED への基本描画 | **確認済み**: 180 度回転描画の確認時に基本描画も動作確認（目視） |
| 180 度回転描画 | 上側プレイヤー向けの反転表示 | **確認済み**: 目視で正常な反転表示を確認 |
| タッチ座標取得 | CST820B からのタッチ座標読み取り | **確認済み**: サンプリング間隔 中央値 15 ms（約 66 Hz）、座標範囲 x 18〜465、y 14〜466 |
| `atan2()` の符号確定 | 画面座標系における時計回り・反時計回りの符号 | **確認済み**: ユーザーから見て時計回りで deg は増加。符号反転は不要 |
| Button A/B | KEYA（GPIO 2）/ KEYB（GPIO 1）の入力取得 | **確認済み**: 画面から見て左＝`M5.BtnA`、右＝`M5.BtnB` |

| バッテリー取得 | バッテリー残量の取得方法と精度 | **確認済み**: `getBatteryLevel()` / `getBatteryVoltage()` 利用可。`getBatteryCurrent()` は使用不可（公式明記）。`isCharging()` は満充電時 false |

| BLE と描画・タッチの同時動作 | BLE advertising と画面描画・タッチの同時利用 | 未実施（将来フェーズ（モバイル連携）の前提条件として残置） |

### 完了条件

実機で決まる定数がすべて実測値で埋まり、描画方式（全画面転送／分割転送／部分更新）が決定していること。

> **現状（2026-08-17 更新）**: デバイス同定・PSRAM 容量・ビルド環境・タッチ座標取得・`atan2()` 符号確定・Button A/B・180 度回転描画・振動の体感確認・バッテリー API・PSRAM 上の全画面 Canvas 確保・描画レート計測が完了し、描画方式が部分再描画に決定した（ADR-15）。**Phase 0 の完了条件（実機で決まる定数が実測値で埋まり、描画方式が決定していること）は達成された。** ただし BLE と描画・タッチの同時動作確認のみが未実施であり、これは将来フェーズ（モバイル連携）の前提条件として残る。Phase 1 に着手できる状態となった。

確認手順の詳細は [開発ワークフロー](./03-dev-workflow.md) を参照のこと。実測記録の詳細は [技術選定記録 - Phase 0 実測記録](./13-decisions.md#phase-0-実測記録) を参照。

- Undo（Button A 短押し、1 回のスライド全体を 1 件として巻き戻す）
- タッチロック（Button B 短押し、タッチ入力のみ無効化）
- 初期ライフ設定画面（外周スライドで開始ライフを増減、A 短押しで 20/40 プリセット切替）
- Rematch（同じ開始ライフでリセット、B 長押し確認あり）
- New Game（初期ライフ設定に戻る、B 長押し確認あり）
- ゲームメニュー（A+B 長押し 1 秒。ボタンのみで操作）
- Swap Sides（上下プレイヤー入れ替え）
- History 画面（直近のライフ変更履歴）
- About 画面（ファームウェア情報）
- 長押し進捗表示（すべての意味のある長押しに弧とテキストで進捗を表示）

## Phase 3: 永続化と電源

データの永続化と電源管理を実装する。

### 実装内容

- **NVS 16 スロットローテーション保存**（名前空間 `lifectr`、キー `s00` 〜 `s15`） — **実装済み**
- **`PersistentRecord` の CRC32 検証** — **実装済み**
- **起動時のゲーム自動復元**（sequence 最大の有効レコードから確認ダイアログなしで復帰） — **実装済み**
- **Sleep 機能の削除**（NVS 永続化により不要となったため、電源 OFF + 自動復元で代替） — **実施済み**
- 90 秒無操作で低輝度へ減光
- 入力発生で通常輝度へ復帰
- バッテリー 20% 以下で警告表示
- バッテリー 10% 以下で定期警告振動
- USB 給電中の充電アイコン表示（`getVBUSVoltage()` による判定。手段は Phase 2 で判明済み）

## クリティカルパスとリスク

### Phase 0 が全体の律速である

Phase 0 の結果が以下を確定させるため、**Phase 0 を最優先で通すこと**が全体スケジュールの律速となる。

- UI 設計の閾値（[UI/UX 設計](./05-ui-ux.md)）: タッチ感度、外周リングの幅、最低移動角
- 描画方式（[アーキテクチャ](./07-architecture.md)）: 全画面転送／分割転送／部分更新の選択
- `atan2()` の符号: 時計回り・反時計回りの判定ロジック

Phase 0 が完了するまで Phase 1 以降の実装パラメータが確定しない。

### BLE 成立性リスク

製品ページでは無線仕様として Wi-Fi のみが明記されている。搭載 SoC の ESP32-S3 は BLE GATT と NimBLE をサポートしているが、M5Stack StopWatch の基板上で BLE・画面描画・タッチの同時利用が可能であるかは要実機確認である。BLE 成立性が否定された場合、モバイル連携フェーズ全体が再設計になる。

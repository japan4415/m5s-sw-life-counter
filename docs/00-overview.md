# プロジェクト概要とスコープ

M5Stack StopWatch Dev Kit を使った Flesh and Blood (FaB) 専用ライフカウンターの設計概要である。

**関連ドキュメント**: [./01-hardware.md](./01-hardware.md) | [./04-requirements.md](./04-requirements.md) | [./05-ui-ux.md](./05-ui-ux.md) | [./12-roadmap.md](./12-roadmap.md)

## 背景と目的

Flesh and Blood は 1 対 1 の対戦カードゲームであり、試合中は両プレイヤーのライフを常に追跡する必要がある。現状の管理手段にはそれぞれ課題がある。

- **紙**: 双方から読みづらく、巻き戻しが煩雑で、変更履歴を追いにくい
- **スマホアプリ**: 画面が片方にしか見えない。大会では電子機器の使用制限があり、Wi-Fi / Bluetooth の利用が問題になり得る
- **汎用ライフカウンター**: FaB 固有のルール（任意の初期ライフ値、開始値超過の増加）に対応しないものが多い

本プロジェクトは M5Stack StopWatch Dev Kit の円形 AMOLED ディスプレイと外周スライド操作を活かし、卓上で双方から視認でき、無線を使わず、FaB のルールに準拠した専用ライフカウンターを開発する。

## プロダクトの形

StopWatch 1 台で 1 対 1 の対戦を管理する。画面は上下に分割され、上半分が対戦相手のライフ（180 度回転表示）、下半分が自分のライフを示す。対戦相手は向かい側から自分のライフを正位置で読み取れる。

背面のマグネットにより、卓上台座（鉄板やマグネット受けを備えた台座）に固定して使用する想定である。USB-C ケーブルを通して給電しながらの長時間利用も可能である。

## FaB ルール由来の要件

FaB では、各ヒーローカードに固有のライフ値が記載されている。そのため設計上、以下の制約を守る必要がある。

| ルール上の事実 | 設計への影響 |
|---|---|
| ヒーローごとにライフ値が異なる | 初期ライフは 20 / 40 固定ではなく、任意値の入力が必須 |
| ライフは開始値を超えて増加できる | 上限クランプを設けてはならない |
| ライフが 0 以下になると敗北 | 0 未満にはクランプするが、0 到達時は操作を制限せず警告のみ表示する |
| 大会ではライフの差異を物理記録で解決する | ペンと紙の併用を運用上推奨する |

## スコープ

### MVP に含む

- 円形画面の外周スライドによるライフ増減（時計回り = 増加、反時計回り = 減少）
- 1 スライド全体を 1 件として記録する Undo
- タッチロック（物理ボタンで切り替え、タッチ入力のみ無効化）
- 初期ライフ設定（20 / 40 / 任意値から選択）
- 電源断後の自動復元（NVS への永続化）
- Tournament Mode（Wi-Fi / Bluetooth を初期化しない標準動作モード）
- 振動フィードバック（音声不使用）
- ゲームメニュー（Resume / History / Set Life / Rematch / New Game / Swap Sides / About）

### MVP に含まない（将来フェーズ）

- スマホ連携（BLE 経由の Android / iPhone アプリ接続）
- 試合記録・統計・ライフ推移グラフ
- クラウド同期・複数端末間の共有
- 2 台の M5Stack 間の同期
- ヒーローデータベース・カード画像表示
- ターンタイマー
- 毒・装備などの追加カウンター

## 設計上の 4 つの原則

### 1. 単独動作が正

スマホやクラウドが存在しなくても全機能が動作する。M5Stack 本体がゲーム状態の唯一の権威（Single Source of Truth）である。将来のモバイル連携でも、スマホ側はレプリカを保持するに過ぎず、M5Stack のイベントログが原本となる。

### 2. 大会で使えることを既定値に

Tournament Mode を標準の動作モードとする。Wi-Fi / Bluetooth を初期化しない、音を出さない、双方から同じ情報が見える、カード名や戦略情報を記録・表示しない。大会規定への適合を「追加設定」ではなく「初期状態」とすることで、設定忘れによる問題を防ぐ。

### 3. 誤操作より取り消しやすさ

完全な誤操作防止は不可能であるため、操作ミスからの回復を容易にする三層の防御を設ける。

1. **外周スライド**: 6 度未満の微小な動きは操作として扱わず、中央へ引き込めばキャンセルできる
2. **Undo**: 1 スライド全体を 1 件として記録し、ボタン 1 押しで正確に取り消せる
3. **タッチロック**: 対戦中に不意のタッチを完全に遮断できる

### 4. 電源断に耐える

確定した操作は必ず NVS に永続化される。許容する損失は「確定途中だった最後の 1 操作」のみである。スライド中（指がまだ画面に触れている状態）の電源断ではそのスライドが破棄されるが、それ以前に確定したすべての操作は復元される。

## 用語集

| 用語 | 定義 |
|---|---|
| FaB | Flesh and Blood。Legend Story Studios が開発・販売するトレーディングカードゲーム |
| ヒーロー | FaB のデッキを代表するカード。ライフ値やヒーロー能力が記載されている |
| Tournament Mode | Wi-Fi / Bluetooth を初期化せず、音声を使わず、戦略情報を記録しない動作モード。本プロジェクトの標準モード |
| Casual Mode | 無線通信を許可し、スマホからのライフ修正やメモ入力を可能にする動作モード。将来フェーズで実装 |
| 外周スライド（Edge Gesture） | 円形画面の外周リング（半径 170 ~ 225 px）をなぞってライフを増減する操作方式。時計回り = 増加、反時計回り = 減少 |
| Undo | 直前のライフ変更を取り消す操作。Button A の短押しで実行する。変更前のライフ値を復元する |
| スナップショット | 現在の試合状態（ライフ値・開始ライフ・変更履歴など）を NVS に保存したバイナリ表現 |
| イベントログ | 各ライフ変更をシーケンス番号付きで記録した時系列データ。将来の LittleFS 移行後は試合ごとのファイルとして管理する |
| Writer Lease | 将来の 2 台スマホ接続時に、書き込み権限を持つスマホを 1 台に限定するための排他制御機構 |
| NVS | Non-Volatile Storage。ESP32 の Flash 上に構築されるキーバリューストア。電源断後もデータが残る |
| PSRAM | Pseudo Static RAM。ESP32-S3 に外付けされた 8MB のメモリ。フレームバッファなどの大きなデータに使用する |

# 電源管理と Tournament Mode

本ドキュメントでは、M5Stack StopWatch ライフカウンターの電源管理方針と、FaB 大会での使用を前提とした Tournament Mode の設計を記述する。

**関連ドキュメント**: [ハードウェア](./01-hardware.md) | [要件定義](./04-requirements.md) | [テスト](./11-testing.md)

---

## 電源状態モデル

### 基本原則: ゲーム進行中は画面を消灯しない

FaB の大会では、ライフカウンターの表示が対戦する双方のプレイヤーから**常に確認可能**でなければならない。したがって、ゲーム進行中に画面を完全消灯する状態遷移は存在しない。

### 状態遷移

```
NORMAL → DIMMED → SCREEN_OFF（セットアップ中のみ）
```

| 状態 | 条件 | 画面 |
|------|------|------|
| NORMAL | 通常操作中 | 通常輝度で表示 |
| DIMMED | 90 秒無操作 | 低輝度へ減光 |
| SCREEN_OFF | セットアップ中に 5 分無操作 | 画面 OFF |

- DIMMED 状態で入力が発生した場合、NORMAL へ復帰し、**その入力も処理する**。復帰のための「空打ち」は要求しない。
- SCREEN_OFF への遷移はセットアップ画面でのみ発生する。ゲーム進行中（ACTIVE 状態）では DIMMED より先へは遷移しない。

## バックライト・輝度制御の方針

| 状態 | 画面 |
|------|------|
| ゲーム進行中 | 消灯しない |
| 90 秒無操作 | 低輝度へ減光 |
| 入力発生 | 通常輝度へ復帰し、その入力も処理 |
| セットアップ中に 5 分無操作 | 画面 OFF |
| バッテリー 20% 以下 | 警告表示 |
| バッテリー 10% 以下 | 定期警告振動 |
| USB 給電中 | 充電アイコン（**注**: 判定手段は判明済み。実装は未適用。下記参照） |

> **解決済み（2026-08-18）: USB 給電中の判定方法**: `isCharging()` は満充電時に false を返すため、USB 給電の有無を正しく判定できない（2026-08-17 実測で確認）。代替手段として **`M5.Power.getVBUSVoltage()`** が使えることが判明した。USB 接続時は約 4800〜5100 mV、未接続時は約 0 mV を返す。満充電時でも USB が接続されていれば値が出る。**`M5.Power.M5pm1.getPowerSource()`** も電源種別の判定に使える。**ただし現時点ではこれらの API を実装に使用していない。** Phase 3 の電源管理で適用する想定である。

## バッテリー目標と測定条件

| 項目 | 値 |
|------|-----|
| 最低目標 | 連続 4 時間 |
| 推奨目標 | 連続 8 時間 |

### 測定条件

- Wi-Fi / Bluetooth 無効
- 輝度 30〜40%
- 振動有効

### バッテリー容量に関する注記

バッテリー容量 450mAh は公式ドキュメントで確認済みである。ただし、**連続稼働時間は未検証であり、実機での測定が必須**である。上記の目標値はあくまで設計上の目標であり、実測結果に基づいて調整する。

### 未達時の対処

- 輝度設定の見直し（30% 以下への引き下げを検討）
- 小型 USB バッテリーの併用

## ハードウェア前提

| 項目 | 値 |
|------|-----|
| 電源管理 IC | M5PM1（マルチレベル電源管理） |
| IO エキスパンダ | M5IOE1 |
| 給電 | USB Type-C DC 5V |
| バッテリー残量確認 | 画面上端から中心へスワイプ |
| バッテリー容量 | 450mAh |
| 背面 | マグネット |

### 電源ボタン操作（公式記載で確定: 2026-08-17）

| 操作 | 動作 |
|------|------|
| 短押し 1 回 | 電源 ON / リセット |
| 素早く 2 回 | 電源 OFF |
| 約 2 秒長押し（緑 LED 点灯まで） | ダウンロードモード |

> **重要（2026-08-18 確認）**: 電源ボタンの押下をアプリから検出することはできない。M5Unified が M5PM1 の IRQ ピン（GPIO12）を設定しないため、`getKeyState()` でボタン押下を取得できない。詳細は [ハードウェア仕様](./01-hardware.md)「電源ボタンの検出制限」を参照。この制限により、スリープ機能はメニュー項目として提供している（ADR-22）。

### 電源レール構造

M5PM1 と M5IOE1 による電源レール構成:

| レール | 供給先 |
|--------|--------|
| L0 | バッテリー → M5PM1 |
| L1 | IMU (BMI270)・RTC (RX8130) |
| L2 | ESP32-S3・M5IOE1 |
| L3A | ESP32-S3・M5IOE1（L2 と共有） |
| L3B | AMOLED・スピーカー・バイブレーションモーター |

> **注記**: AMOLED とバイブレーションモーターは M5IOE1 配下の電源レール L3B にぶら下がる。M5IOE1 経由での電源制御が必要。

> **ラベル誤記注意**: 公式ドキュメントに「`BAT` と表記されたピンは実際には `5V IN`（外部電源入力用）であり、バッテリー接続ではない」という注記がある。

### バッテリー API の実測結果（2026-08-17）

| API | 戻り値 | 利用可否 | 備考 |
|---|---|---|---|
| `M5.Power.getBatteryLevel()` | 0〜100（%） | **可** | USB 接続・満充電時に 100 を返すことを確認 |
| `M5.Power.getBatteryVoltage()` | mV 単位 | **可** | |
| `M5.Power.isCharging()` | bool | **条件付き** | 満充電時は false を返す（下記注意参照） |
| `M5.Power.getBatteryCurrent()` | -- | **不可** | ハードウェア制限により StopWatch ではバッテリー電流を読み取れない（公式記載） |
| `M5.Power.getVBUSVoltage()` | mV 単位 | **可** | USB 給電判定に使用可能。USB 接続時 約 4800〜5100 mV、未接続時 約 0 mV（2026-08-18 確認） |
| `M5.Power.M5pm1.getPowerSource()` | 列挙値 | **可** | 電源種別の判定に使用可能（2026-08-18 確認） |

> **`isCharging()` の制限**: USB 接続中・満充電時に `isCharging()` = false（0）が返った。満充電になると充電回路が停止するため `isCharging()` は false になる。**`isCharging()` を「USB 給電中かどうか」の判定に使うのは不適当**である。

> **解決済み（2026-08-18）**: USB 給電判定の代替手段として `getVBUSVoltage()` と `getPowerSource()` が使えることが判明した。**ただし現時点ではこれらの API を実装に使用していない。** Phase 3 の電源管理で適用する想定である。

## スリープ機能（Phase 2 実装済み・実機確認済み: 2026-08-18）

ゲームメニューの Sleep 項目を選択すると、ESP32-S3 のライトスリープに入る。

### ライトスリープのみを使う理由

**`deepSleep` / `powerOff` / `timerSleep` は使わない。** 永続化（Phase 3）が未実装のため、RAM を失うと試合状態（ライフ値、履歴、設定）が消失する。**`lightSleep` だけが RAM を保持する**ため、スリープからの復帰後に試合をそのまま再開できる。Phase 3 で NVS への永続化が実装された後は、deepSleep の採用を再検討できる。

### 復帰手段を必ず 2 つ用意する方針

**スリープには必ず復帰手段を 2 つ用意する。**

1. **GPIO ウェイクアップ**: A ボタン（GPIO 2）または B ボタン（GPIO 1）の押下で復帰する
2. **タイマーウェイクアップ**: 30 秒経過で自動復帰する（安全策）

**この方針の根拠**: ライトスリープを GPIO ウェイクアップのみで実装した際に、ESP32-S3 の GPIO スリープ設定の問題（M5Unified の `pinMode(INPUT)` が SLP_PU をクリアする）によりスリープから復帰できず、USB シリアルも消失して書き込み不能になる事故が発生した。タイマー復帰を安全策として併用していれば、GPIO ウェイクアップが効かなくても 30 秒後に自動復帰できる。詳細は [ハードウェア仕様](./01-hardware.md)「ライトスリープでの GPIO 設定の罠」を参照。

### スリープの実装詳細

- **画面制御**: スリープ前に `M5.Display.sleep()` で画面を消灯し、復帰後に `M5.Display.wakeup()` で点灯する
- **GPIO 設定**: スリープ前に `gpio_sleep_sel_dis(pin)` で SLP_SEL を無効化し、`gpio_set_direction(INPUT)` と `gpio_pullup_en()` を明示的に呼ぶ
- **復帰後の入力抑制**: 両方のボタンが離されるまで入力を抑制する。カーソルが Sleep 上にあるため、復帰に使ったボタンを離した瞬間に Sleep が再実行されることを防ぐ

### 電源ボタンによるスリープが実装できない理由

電源ボタンの押下をアプリから検出できないため（「電源ボタン操作」節の注記を参照）、「電源ボタンを押したらスリープに入る」という一般的な操作は実装できない。代替として、ゲームメニューの項目として Sleep を提供している（ADR-22）。

## 省電力の実装指針

### 無線を初期化しない

Tournament Mode（標準動作）では Wi-Fi および Bluetooth を**初期化しない**。無線モジュールを起動しないこと自体が最大の省電力策である。ESP32-S3 の無線モジュールは消費電力の大きな要因であり、初期化を行わないことでバッテリー持続時間に大きく寄与する。

### 描画頻度の抑制

画面描画は変更が発生した場合にのみ行う。毎フレーム全画面を再描画するのではなく、`renderIfDirty()` パターンで状態変更時のみ Canvas を転送する。描画方式の詳細は [アーキテクチャ](./07-architecture.md) を参照。

### 振動の使用時間

振動モーターは短時間のパルス（10〜150ms）で使用する。長時間の連続振動は避ける。

### 非ブロッキングループとの関係

メインループでは `delay()` を使用しない。`millis()` または ESP-IDF の単調増加タイマーによる非ブロッキングループで制御する。これにより、入力の応答性を維持しつつ、不要な CPU サイクルの消費を抑える。メインループの構造については [ソフトウェアアーキテクチャ](./07-architecture.md) を参照。

非ブロッキングループにより、`powerManager.tick()` が毎ループ呼ばれるため、減光からの復帰判定やバッテリー監視が即座に反応できる。また、振動パターン再生中でも画面更新や入力処理と干渉しない。

---

## Tournament Mode（標準動作）

本アプリケーションの既定の動作モードである。以下の制約をすべて満たす。

- Wi-Fi を初期化しない
- Bluetooth を初期化しない
- 外部通信を行わない
- ライフとライフ変更履歴だけを記録
- カード名・手札・ピッチ順・戦略メモを記録しない
- 双方から常に同じ情報を閲覧可能
- 音声を使用しない
- OTA アップデートを搭載しない
- 画面を完全消灯しない

---

## なぜ既定値が Tournament Mode なのか

設計原則: **大会で使えないモードを既定にしない。**

FaB の大会では電子機器の使用に制限がある。無線通信を行うデバイスや、対戦相手から確認できない情報を表示するデバイスは、ヘッドジャッジの判断で使用が禁止される可能性がある。Tournament Mode を既定とすることで、ユーザーが設定を変更せずとも大会で使用可能な状態を保証する。

Casual Mode はモバイル連携フェーズ（[モバイル連携](./10-mobile-integration.md) 参照）で追加される拡張であり、MVP スコープには含まれない。

**試合開始後はモード切り替え不可**である。これはモード切り替えによる中途半端な記録状態を防ぐための設計判断である。

---

## FaB 大会規定に関する注意

以下は製品仕様ではなく**運用要件**である。

- **Competitive / Professional REL のドラフト中は電子機器使用不可**である。ドラフトフェイズではライフカウンターを含むすべての電子機器を使用できない。
- **ヘッドジャッジが追加制限を設けられる。** 大会ごとに電子機器の使用可否が異なる場合がある。
- **ライフ差異の解決では物理記録が優先される。** 電子ライフカウンターの値と物理的な記録（ペンと紙、ダイス等）に食い違いがある場合、物理記録が正とされる。

### 運用上の推奨事項

- 使用前にヘッドジャッジへ確認すること
- ペンと紙、または物理カウンターも併せて携帯すること
- 本デバイスを唯一のライフ記録手段としないこと

## 卓上台座

M5Stack StopWatch は背面マグネットを備えているが、大会環境での安定した設置には卓上台座の使用を推奨する。

### 推奨スペック

| 項目 | 推奨値 |
|------|--------|
| 重量 | 100〜200g |
| 上面 | 鉄板またはマグネット受け |
| 底面 | 滑り止めゴム |
| 姿勢 | 水平保持 |
| ケーブル | USB-C ケーブル用の切り欠き |
| ボタン | 物理ボタンを塞がない設計 |
| 保護 | 画面周囲に 2〜3mm の保護縁 |

### 3D プリントの場合

底面に金属ワッシャーを内蔵することで、重量の確保とマグネットによる本体固定を同時に実現できる。

## 検証項目

以下の項目は実機での検証が必須である。詳細なテスト手順は [テスト](./11-testing.md) を参照。

| 検証項目 | 目的 |
|---------|------|
| 稼働時間実測 | 450mAh バッテリーでの連続稼働時間が目標（4〜8 時間）を満たすか確認 |
| 視認性 | 60〜80cm の距離から数字が読めるか確認（大会環境での対戦相手からの視認性） |
| 低バッテリー時の表示 | バッテリー残量が低下してもライフ表示が失われないこと |
| 電源 OFF 操作 | **確認済み**（公式記載）。短押し 1 回=ON/リセット、素早く 2 回=OFF、約 2 秒長押し=ダウンロードモード |
| 減光からの復帰 | DIMMED 状態からの入力で即座に NORMAL へ復帰し、入力が処理されること |

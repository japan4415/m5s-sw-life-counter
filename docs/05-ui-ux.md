## 画面レイアウト

468 x 468 px の円形 AMOLED ディスプレイを使用する（`M5.Display.width()` / `M5.Display.height()` の実測値。公式製品ページの仕様表記は 466 x 466 px であり食い違っているが、設計は実測値を採用する。ロット差やライブラリ更新で変わりうるため、公式値との乖離を認識しておくこと）。中心座標は (234, 234) である。画面を上下に分割し、上半分を対戦相手（180 度回転描画）、下半分を自分として表示する。回転は鏡映ではなく 180 度回転である。

```
上側プレイヤー
        40
        - ↺  ↻ +
╭─────────────────╮
│                 │
│                 │
│                 │
╰─────────────────╯
        + ↻  ↺ -
        40
下側プレイヤー
```

外周リングがライフ操作領域、中央が表示専用領域、物理ボタンが Undo・ロック・メニューの役割を担う。タッチ操作とボタン操作が明確に分離されている。

## タッチ領域の定義

円形画面上のタッチ領域を同心円で分割する。外周リング下限は Phase 0 Step 3 実測（2026-08-17、826 サンプル）で確定した値である。それ以外の数値は設計上の初期値であり、実機テストで調整する前提である。

| 領域 | 半径範囲 (px) | 用途 |
|------|-------------|------|
| 外周操作リング | 165 以上（上限なし） | ライフ増減のスライド操作。下限 165px は実測 p0（最小タッチ半径）に基づく。タッチ IC は表示領域外（半径 234px 超、最大 268px）の座標も返すため上限を設けない |
| 表示領域 | 0〜164 | ライフ値・差分・アイコンの表示専用。タッチ操作の対象外 |
| キャンセル領域 | 145 未満 | スライド中に指がこの領域に入ると操作をキャンセルする。設計値据え置き（リング下限 165 との間に 20px のヒステリシス） |

判定コード（定数は実際には `config/app_config.hpp` に集約する）:

```cpp
// 以下の定数は config/app_config.hpp で定義する設定定数。
// ここではロジックの説明のためにリテラルで記述している。
float dx = touchX - 234.0f;  // kDisplayCenterX
float dy = touchY - 234.0f;  // kDisplayCenterY
float radius = std::sqrt(dx * dx + dy * dy);
bool isEdgeRegion = radius >= 165.0f;  // kEdgeInnerR（実測 p0。上限なし）
```

## プレイヤー選択

タッチ開始地点の y 座標で操作対象プレイヤーを決定する。

```cpp
// kDisplayCenterY は config/app_config.hpp で定義する設定定数（実測値 234）。
PlayerId selectPlayer(int16_t touchY) {
    return touchY < 234 ? PlayerId::Top : PlayerId::Bottom;  // kDisplayCenterY
}
```

### 開始許可領域と禁止領域

外周リング上のタッチ開始位置を角度で制限し、左右の境界付近での誤操作を防止する。

| 領域 | 角度範囲 | 動作 |
|------|---------|------|
| 上側プレイヤー開始領域 | 200度〜340度（上側 140 度） | 上側プレイヤーの操作を開始できる |
| 下側プレイヤー開始領域 | 20度〜160度（下側 140 度） | 下側プレイヤーの操作を開始できる |
| 左右の開始無効領域 | 各 20 度（160度〜200度、340度〜20度） | タッチ開始を受け付けない。警告振動のみ |

操作開始後は対象プレイヤーを固定する。スライド中に指が上下の境界を越えても操作対象は変更しない。

## スライド量とライフ変動

ライフの増減量は移動距離ではなく、中心からの角度（中心角）の変化量で計算する。

**デフォルトでは 36 度移動ごとにライフ ±1**（一周 360 度で 10 ライフ分）。Phase 1 実機評価（2026-08-17〜18）でユーザーが「ちょうど良い」と評価し確定した値をデフォルトとして採用している。半径 200px 付近では約 126px の弧長に相当する。感度の決定経緯は [ADR-18](./13-decisions.md) を参照。メニューの Sensitivity 設定で 5 / 10 / 20 ライフ/周（72 / 36 / 18 度/ライフ）から変更可能である（#38）。

| スライド角 | ライフ変動 |
|-----------|-----------|
| 時計回り 36 度 | +1 |
| 時計回り 108 度 | +3 |
| 反時計回り 144 度 | -4 |
| 36 度未満 | 変更なし |

### 感度の確定

Phase 1 実機評価（2026-08-17〜18）で **36 度/ライフ（一周 10 ライフ）** をデフォルト値として確定した。旧設計値 10 度/ライフ（一周 36 ライフ）で実機を操作したところ「速すぎる。一周で 10 にしてほしい」という評価があり、36 度/ライフに変更された。実測のスイープ角速度 約 233 度/秒から、ライフ 1 段階あたり約 **154 ms** で到達する（旧値では約 43 ms）。#38 でこのデフォルト値を基準としつつ、メニューの Sensitivity 設定で 5 / 10 / 20 ライフ/周（72 / 36 / 18 度/ライフ）から選択可能になった。

### 方向の意味

- **時計回り = ライフ増加**
- **反時計回り = ライフ減少**

上下どちらのプレイヤーでも回転方向の意味は反転しない。180 度回転描画は鏡映ではないため、両プレイヤーとも同じ方向規則が適用される。

## ジェスチャーの状態遷移

外周スライド操作は 4 つの状態で管理する。

```
Idle
↓ 外周に触れる
Candidate
├─ 6度以上移動  → Active
├─ 指を離す    → Idle、変更なし
└─ 中央へ移動  → Cancelled

Active
├─ 円周方向に移動 → プレビュー更新
├─ 中央へ移動   → Cancelled
└─ 指を離す    → 変更確定

Cancelled
└─ 指を離す → Idle
```

状態モデル:

```cpp
enum class GestureState { Idle, Candidate, Active, Cancelled };

struct EdgeGesture {
    GestureState state;
    PlayerId player;
    float startAngle;
    float previousAngle;
    float accumulatedAngle;
    float startRadius;
    int32_t previewDelta;
    uint32_t originalLife;
    uint32_t startedAtMs;
    uint32_t previousSampleMs;
};
```

各遷移条件:

| 遷移 | 条件 |
|------|------|
| Idle → Candidate | 外周操作リング（半径 165px 以上）でタッチ開始、かつ開始許可領域内 |
| Candidate → Active | 累積移動角が 6 度以上（設計上の初期値） |
| Candidate → Idle | 移動角 6 度未満で指を離す。操作として扱わない |
| Candidate → Cancelled | 指が半径 145px 未満に移動 |
| Active → Active | 円周方向に移動。プレビュー値を更新し振動フィードバック |
| Active → Cancelled | 指が半径 145px 未満に移動 |
| Active → Idle | 指を離す。変更を確定し履歴に 1 件として記録 |
| Cancelled → Idle | 指を離す。変更は適用されない |

## 角度計算と境界またぎ補正

角度は `atan2()` で計算する。360 度 / 0 度の境界をまたぐ際のデルタ値を正規化する。

```cpp
float normalizeDelta(float delta) {
    while (delta > M_PI)  delta -= 2.0f * M_PI;
    while (delta < -M_PI) delta += 2.0f * M_PI;
    return delta;
}

void onTouchMove(float x, float y) {
    if (!gesture.active) return;
    float angle = std::atan2(y - centerY, x - centerX);
    float delta = normalizeDelta(angle - gesture.previousAngle);
    gesture.accumulatedAngle += delta;
    gesture.previousAngle = angle;
    int32_t newSteps = static_cast<int32_t>(gesture.accumulatedAngle / radiansPerLife);
    if (newSteps != gesture.previewSteps) {
        gesture.previewSteps = newSteps;
        updatePreview();
        hapticTick();
    }
}
```

**`atan2()` の符号（Phase 0 Step 3 実測で確定）**: 画面座標系は y 軸が下向きに増加するため、数学的な標準座標系（反時計回りが正）とは逆に、**ユーザーから見て時計回りになぞると `atan2()` の角度は増加する**。したがって累積角度が正＝ライフ増加であり、符号の反転処理は不要である（Phase 0 Step 3 実測、2026-08-17、826 サンプルで確認。一周あたり +363.6 度 / −372.3 度を記録）。

## 誤操作防止の仕組み

外周スライド方式には 4 つの誤操作防止機構を組み込む。

### 1. 最低移動角

```cpp
// タップだけでは変更しない（最低移動角：6度）
if (std::abs(accumulatedAngle) < activationAngle) { previewSteps = 0; }
```

累積移動角が 6 度未満（設計上の初期値）の場合は操作として扱わない。外周に触れただけ、あるいは微小な移動では値が変わらない。

### 2. 対象プレイヤー固定

```cpp
// 対象プレイヤーを固定
gesture.player = selectPlayer(touchStart);  // 移動中に上下境界を越えても変更しない
```

タッチ開始時に決定した対象プレイヤーを操作終了まで固定する。スライド中に指が上下の境界を越えても対象は切り替わらない。

### 3. 中央引き込みキャンセル

```cpp
// 中央へ大きく移動でキャンセル
// 半径145px未満まで内側へ移動 → 操作キャンセル
```

スライド中に指を画面中央方向へ引き込み、半径 145px 未満（設計上の初期値）に達すると操作全体をキャンセルする。

### 4. 異常な角速度のサンプル除外

```cpp
// 角速度で異常値を判定（絶対角度ではなくサンプル間の経過時間を考慮）
// deltaMs が 0 のサンプルはゼロ除算を避けて無視する
float angularSpeed = std::abs(deltaDeg) / static_cast<float>(deltaMs);  // 度/ms
if (deltaMs == 0 || angularSpeed > 0.7f) {  // kMaxAngularSpeed
    // このサンプルを無視する
}
```

1 サンプルあたりの絶対角度ではなく、サンプル間の経過時間を考慮した角速度で異常値を判定する。実測（Phase 0 Step 3、2026-08-17、826 サンプル）ではサンプル間隔の中央値が 15 ms（約 66 Hz）だが最大 270 ms の欠測が発生する。絶対角度しきい値（旧: 30 度/サンプル）では、正当な操作が誤って除外される（例: 角速度 233 度/秒で 270 ms の欠測後に約 63 度のジャンプが発生）。

しきい値の初期値 0.7 度/ms（700 度/秒）は、実測の快適な操作時の角速度（約 0.233 度/ms）の約 3 倍に設定している。**この値はまだ実機で検証していない初期値であり、さらなる実機評価で調整しうる**。

## プレビューと確定

スライド操作中はリアルタイムでプレビュー値を画面に表示し、指を離した時点で確定する。

### 表示内容

- スライド中: 操作対象プレイヤーのライフ表示をプレビュー値に更新し、差分（例: `-4`）を画面中央に表示する
- 確定時: プレビュー値をライフに適用し、履歴に 1 件として記録し、永続化をスケジュールする

### 方向反転の例

反時計回りに 5 段階スライド → 時計回りに 2 段階戻す → 指を離す → **`-3` で確定**。履歴には 1 件として記録される。`-5` と `+2` の 2 件ではない。

### 確定処理

```cpp
void commitGesture() {
    if (gesture.previewDelta == 0) return;
    applyLifeChange(gesture.player, gesture.previewDelta);
    history.push({
        .player = gesture.player,
        .before = gesture.originalLife,
        .after = currentLife,
        .delta = actualDelta,
    });
    storage.scheduleSave();
}
```

## 表示ルール

状態に応じた表示パターンを以下に定義する。色覚差に依存せず、アイコン・枠線・振動を併用してすべての状態を伝達する。

| 状態 | 表示 |
|------|------|
| 通常 | 白い数字、黒背景 |
| 直前に変更 | 変更した側を一瞬明るくし、`-3` や `+1` を約 1.5 秒表示 |
| ライフ 0 | 数字を強調し、警告アイコンと強い振動 |
| ロック中 | 中央に鍵アイコン、タッチ領域を薄暗く表示 |
| バッテリー低下 | 中央にバッテリー警告 |
| 復元直後 | 「前回のゲームを復元しました」を短時間表示 |

### 操作中の表示

- 通常時: 上下両方の外周を薄く表示
- 操作中: 対象プレイヤー側の外周を強調し、非対象側を暗くする

### 色覚対応方針

色の違いだけで情報を伝えない。以下の手段を併用する:
- アイコン（鍵・警告・バッテリー等）
- 枠線の太さ・スタイル変化
- 振動パターンの違い
- テキスト情報（差分値等）

## 振動フィードバック設計

音声を使用せず、すべてのフィードバックを振動で行う。

### API の動作（Phase 0 Step 5 実測、2026-08-17）

`M5.Power.setVibration(uint8_t level)` は**強度指定**（0〜255）であり、時間指定ではない。`level` を 1〜255 に設定するとモーターが回り続け、**`setVibration(0)` を明示的に呼ぶまで停止しない**。内部実装は M5IOE1 の `pwm_ch1`（GPIO9）へ 12bit PWM を出力する（`duty12 = level * 0x0FFF / 255`）。

したがって振動パルスの制御は以下の 2 段階になる:

1. `setVibration(255)` で開始
2. 所定の時間を `millis()` で非ブロッキングに計測し、`setVibration(0)` で停止

この待ち時間に `delay()` は使用しない。`Haptics` コンポーネントの `tick()` で毎ループ経過時間を確認する（[アーキテクチャ](./07-architecture.md) 参照）。

### 強度と時間の実測結果

| 条件 | 結果 |
|------|------|
| 強度 32〜192 | 体感できない |
| 強度 **255** | 体感できる |
| 時間 15 ms（強度 255） | かろうじて感じる |
| 時間 **20 ms**（強度 255） | 確実に感じる |

**結論**: 強度は設計変数にならない。**255 固定**とする。振動の強弱は**時間の長短でのみ区別する**。

### 振動パターン

以下の値は実測（20 ms が確実に体感できる下限）に基づく提案値である。**通しでの体感評価はまだ行っていない**ため、実機での統合テスト後に調整しうる。

| 操作 | 時間 (ms) | 強度 | 旧設計値 | 変更理由 |
|------|-----------|------|---------|---------|
| スライド操作開始 | 30 | 255 | 30ms | 変更なし（下限 20ms 超） |
| ±1 を通過 | 20 | 255 | 10〜15ms | 旧値は体感下限 20ms 未満のため引き上げ |
| 指を離して確定 | 40 | 255 | 40ms | 変更なし（下限 20ms 超） |
| キャンセル | 20 x 2 回（間隔 60ms） | 255 | 短い振動 x 2 回 | 「短い」を 20ms に具体化。強度による区別は不可 |
| ライフ 0 到達 | 120 | 255 | 100〜150ms | 範囲から中間値に具体化 |
| 開始禁止領域 | 20 | 255 | 弱い振動 x 1 回 | 「弱い振動」は強度では実現不可。最短パルス（20ms）で代用し、他パターンとの時間差で区別する |

### 高速入力時の振動間引き（現時点では不要）

Phase 1 実機評価（2026-08-17〜18）の結果、感度を 36 度/ライフに変更したこと（ADR-18）により、間引きは**現時点では不要**になった。ADR-17 で検討されていた 2 案のうち、案 B（感度引き下げ）が選ばれた形である。

**根拠**:

- タッチのサンプリング間隔中央値: 15 ms（Phase 0 Step 3 実測）
- 実測のスイープ角速度: 約 233 度/秒（Phase 0 Step 3 実測）
- 感度 36 度/ライフの場合、ライフ 1 段階あたり約 **154 ms** で到達する
- 20 ms の振動パルスを毎段階入れた場合のデューティ比は **20 / 154 ≒ 13%**
- デューティ 13% は十分にクリック感として体感でき、連続振動にはならない

**旧設計（感度 10 度/ライフ）との比較**:

| 感度 | 1 段階あたりの時間 | デューティ比 | 判定 |
|------|-------------------|-------------|------|
| 10 度/ライフ（旧） | 約 43 ms | 20 / 43 ≒ **47%** | 連続振動。フィードバックとして機能しない |
| 36 度/ライフ（現行） | 約 154 ms | 20 / 154 ≒ **13%** | クリック感として十分。間引き不要 |

**実装上の扱い**: `src/infra/haptics_m5.cpp` の間引きロジックは削除せず `kStepThrottleEnabled = false` で無効化してある。将来、感度を上げ直した場合（段階あたりの時間が短くなった場合）に間引きを再有効化できるようにするためである。間引きの方式選定（ADR-17）の詳細は [設計判断記録](./13-decisions.md) を参照。

## 物理ボタン

M5Stack StopWatch のプログラマブルボタン 2 個と電源ボタンを使用する。

| ボタン | GPIO | 操作 | 動作 |
|--------|------|------|------|
| KEYA（黄） | GPIO 2 | 短押し | Undo（直前の操作を取り消す） |
| KEYB（青） | GPIO 1 | 短押し | タッチロック / 解除 |
| KEYA + KEYB | GPIO 2 + GPIO 1 | 長押し（1 秒） | ゲームメニューを開く |

タッチロック中もすべての物理ボタン操作は有効である。

**ボタンの物理配置（実機確認済み）**: 画面正面から見て**左のボタンが BtnA（KEYA）、右のボタンが BtnB（KEYB）**である。したがって Undo（A）は左、タッチロック（B）は右に配置される。

> **注記**: 電源ボタンはアプリからの押下検出ができないため（[ハードウェア仕様](./01-hardware.md)「電源ボタンの検出制限」参照）、ソフトウェアによる電源制御は行っていない。Sleep 機能は NVS 永続化の導入により廃止された（ADR-24）。

## 画面遷移

実装の `Screen` 列挙は **Setup / Active / Menu / History / About / Sensitivity** の 6 つである。

```
SETUP ── B(hold) 1秒 ──→ ACTIVE
                           ↕ A+B(hold) 1秒
                          MENU
          ┌────────┬──────┼──────────┬───────┬───────┐
        Resume  History  SetLife  Sensitivity  Rematch  About
          ↓       ↓       ↓         ↓        B(hold)確認  ↓
        ACTIVE  HISTORY  SETUP  SENSITIVITY    ACTIVE   ABOUT
                  ↓                 ↓                     ↓
             B短押し→ MENU   B短押し/A+B→ MENU      B短押し→ MENU
```

### 状態の説明

| 状態 | 説明 |
|------|------|
| SETUP | 初期ライフ設定画面。外周スライドで各プレイヤーの開始ライフを増減する |
| ACTIVE | ゲーム進行中。外周スライドと物理ボタンによる操作を受け付ける |
| MENU | ゲームメニュー表示中。ボタンのみで操作する |
| HISTORY | 直近のライフ変更履歴を一覧表示する |
| ABOUT | ファームウェア情報を表示する |
| SENSITIVITY | 感度設定画面。一周あたりのライフ変動量を 5 / 10 / 20 から選択する |

**ロック（LOCKED）は画面状態ではない。** 実装では `MatchState::touchLocked` のフラグとして保持する。ロック中もメニューやボタン操作は通常どおり動作し、タッチ入力のみが無効化される。画面遷移として扱う必要がないため、独立した Screen にしなかった。

**ライフ 0 は独立した画面状態にしない。** `life == 0` から導出される表示状態（警告アイコン・強い振動）として扱う。ライフ 0 でもすべての操作（Undo・増加・メニュー）が可能である。

### 電源状態

| 状態 | 条件 |
|------|------|
| NORMAL | 通常輝度 |
| DIMMED | ゲーム進行中に 90 秒無操作で遷移。入力で NORMAL へ復帰（その入力も処理する） |
| SCREEN_OFF | セットアップ中のみ、5 分無操作で遷移 |

## セットアップ画面とゲームメニュー

### セットアップ画面（Phase 2 実装で確定: 2026-08-18）

初期ライフ設定画面では、製品の中心操作である**外周スライド**をそのまま再利用し、各プレイヤーの開始ライフを直接増減する。

- **外周スライド**: 上半分をスライドすると相手の開始ライフを増減、下半分をスライドすると自分の開始ライフを増減する。Active 画面と同じ操作感で任意値を入力できる
- **A 短押し**: 上下両方の開始ライフを 20 / 40 のプリセットで切り替える（トグル）
- **B(hold) 長押し（1 秒）**: START（試合を開始する）。誤操作防止のため短押しでは開始しない

### ゲームメニュー

A+B(hold) 長押し（1 秒）で表示するメニュー項目（6 項目、項目間隔 24px、y=157〜277）:

| メニュー | 動作 | 確認 |
|---------|------|------|
| Resume | ゲームに戻る | なし |
| History | 直近のライフ変更履歴を表示 | なし |
| Set Life | Setup 画面に遷移し、現在のライフを直接修正 | なし |
| Sensitivity | 感度設定画面に遷移し、一周あたりのライフ変動量を変更 | なし |
| Rematch | 同じ開始ライフに戻す | B(hold) 長押し確認を要求 |
| About | ファームウェアバージョン表示 | なし |

> **注記**: メニューは 6 項目。Swap Sides は使用しないため削除された（ADR-26、#16）。New Game は Rematch に統合された（ADR-25、#15）。開始ライフの変更は Set Life で行う。Sleep は NVS 永続化の導入により廃止された（ADR-24）。Sensitivity は #38 で追加された。

### バッテリー表示（メニュー画面、Phase 2 実装済み・実機確認済み: 2026-08-18）

メニュー画面に**電池アイコン（図形描画）＋パーセント**を表示する（y=138）。

- **図形で描画**: M5GFX の標準フォントでは絵文字（電池アイコン等）が出ないため、矩形と塗りで電池アイコンを図形描画している
- **残量に応じて内部を塗る**: 残量に比例して電池内部の塗り面積を変える
- **20% 以下は警告表現**: オレンジ色＋太枠＋`!` マークの三重表現で警告する。色だけに頼らず、太枠と `!` マークを併用して色覚差に依存しない設計としている
- **充電中は稲妻マークを描く**: `isCharging()` が true のとき、電池内部に稲妻マークを描画する。`isCharging()` が false のとき（満充電時を含む）は稲妻マークを付けない

## 大きな値の入力

デフォルト感度（36 度/ライフ、10 ライフ/周）の場合、20 点の変更には 720 度（2 周）のスライドが必要となる。FaB の初期ライフ 40 をゼロにするには 1,440 度（4 周）が必要である。実測の快適なスイープ所要時間は一周あたり約 2.9〜3.5 秒であるため、40→0 の操作には約 12〜14 秒を要する計算になる。感度を 20 ライフ/周（18 度/ライフ）に変更すれば 2 周で済み、5 ライフ/周（72 度/ライフ）では 8 周が必要になる。

**Phase 1 実機評価（2026-08-17〜18）でのユーザー評価**: この操作コストは「ちょうど良い」と評価された。旧設計値（10 度/ライフ、一周 36 ライフ）の「速すぎる」という問題が解消され、意図的な操作感が得られている。大きな値の変更は Set Life メニューによる直接入力でも対応可能である。

**MVP の方針**: 加速なし（デフォルト 36 度固定、Sensitivity 設定で変更可能）で実装する。実際の使用で不便が確認された場合に加速機構を追加する。

加速を追加する場合の検討事項:
- 一定速度以上のスライドで感度を上げる
- 累積角が一定以上で感度を切り替える
- Set Life メニューによる直接入力を代替手段とする
